## Repository-specific records

### D06 — ChromaFlora native platform: procedural garden, instrument, and maker studio

**Use when:** When recovering chromaflora-sitezip's original platform, ChromaSynth, mandala studio, native browser tools, or plotter/export ambitions.

[Recovered intent] The native ChromaFlora README imagines a cosmic bioluminescent platform: procedural galleries, an art studio, harmonic audio synthesis, digital-to-physical exports, embed variants, creator participation, and a marketplace. Its distinctive promise is formula-derived imagery using browser-native Canvas, CSS, Web Audio, and local state.

[Design DNA] Preserve luminous cosmic color, mathematical ornament, playable sound, generative composition, and the ability to understand what produced a result. A living garden can be an instrument, a studio, and a publishing surface; these are separate workflows.

[Observed boundary] The README describes twenty pages and multiple capabilities, but this pass did not execute them. Community, account, payment, admin, inference, and machine-output claims cannot be inferred from static pages or localStorage. The legacy README inside Prime is a derivative portfolio package, not proof that the two runtimes are interchangeable.

[Repair resolution — proposed] Recover working native generators and export contracts before rewriting into a framework. Assign each page a role and data authority. Retain local-only creation as a usable product. Connect real account/community/checkout services only after their contracts and need are demonstrated. Machine exports remain draft until process-qualified.

[Reimagined horizon] An open, playful creative garden with a coherent studio workspace, a ChromaSynth performance mode, a gallery of reproducible recipes, and optional creator publishing. Reuse kernel functions; let the native platform and Prime narrative runtime remain distinct products.

[Carry-forward test] A seeded artwork/audio recipe survives save/reload and export, with a rendered preview matching the actual output and an honest local/cloud capability label.

### D07 — ChromaFlora Prime: a narrative runtime with coupled sensory channels

**Use when:** When designing Prime's fluid-glass experience, narrative states, spectral effects, audio, recovery, or migration from earlier blueprints.

[Recovered intent] Prime is an adaptive narrative experience, not FLORÉ with neon colors. The six-state arc is pristine → awakening → corrupted → fragmenting → authenticated → transcendent. The earlier master bundle includes a performance core, elastic cursor, glass cards, SpectralInk, LightLeak, AetherWarp, and SingularitySupernova. The full horizon includes transformation and recovery, not simply a first-screen effect.

[Observed implementation] Current package scripts use Next, with React/R3F, Three, Framer Motion, Zustand, and Web Audio dependencies. The inspected narrative module maps states to corruption and audio tones. The store contains chapter/glitch/UI state, but those declarations alone do not prove every channel is coupled.

[Repair resolution — proposed] Create one channel matrix per narrative state: semantic meaning, trigger, allowed transitions, corruption, color, geometry, audio, motion, navigation, sensory cap, fallback, and recovery. Distinguish narrative “authenticated” from actual account authentication. Mark unconnected channels explicitly.

[Architecture correction] The older blueprint prescribes Vite development and Next production without demonstrating that bridge. Preserve it as an abandoned/provisional option; use the repository's actual build authority unless a separate Vite instrument is intentionally introduced. Avoid competing animation writers. Keep raw pointer signals in refs/motion values; commit semantic events to state.

[Reimagined horizon] An expressive digital garden whose emotional progression is inspectable and replayable. A low-motion or muted route preserves the same narrative decisions. Reusable optical mechanisms may graduate to AETHER only after a stable independent contract.

[Carry-forward test] Run the six-state scenario with audio off/on and reduced motion. Compare expected/observed channel outputs, interruption/recovery, browser hydration, and a clean build. Old $115,000 labels, 60/120fps claims, and checkmark-filled bundles are not measured delivery value or proof.

## Practical continuation contract

1. Re-read current repository instructions and source before implementation. The baseline above identifies this publication, not a permanent execution HEAD.
2. Retain the full design horizon separately from the current demonstrator. Name what the demonstrator preserves, approximates, defers, or cannot prove.
3. Map tokens and controls to actual consumers with explicit units, ownership, accessible alternatives, and observable effect.
4. Complete the relevant interaction/error/cancellation states before promoting a reusable component.
5. Pair source/runtime checks with human correspondence review against the actual visual inspiration.
6. Keep proposed repairs unexecuted until a later implementation records its own revision, checks, and evidence.
